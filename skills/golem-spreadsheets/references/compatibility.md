# Compatibility and fidelity contract

Versioned engines: vendored SheetJS CE 0.20.3, Apache-2.0, official CDN tarball with SHA-256 and npm integrity lock; LibreOffice from the Ubuntu snapshot distribution. The deployment target is Ubuntu only; no Windows/Excel worker, Microsoft Office automation or commercial license is required or assumed. File-format compatibility does not prove execution in every historical Excel application/version.

- XLSX/XLSM/XLTX/XLTM (Excel 2007+): read, create, cell edit, conversion. Default edits preserve untouched package bytes; VBA/objects are not executed or rewritten. New formulas request recalculation on open. Signed, protected and shared/array-formula edits fail closed. Full arbitrary visual/structural editing is not promised.
- XLS BIFF8 (Excel 97–2003/2004): read, data write. Use LibreOffice for formulas; whole-book rewriting may change advanced objects, so retain the input and acknowledge fidelity trade-offs.
- XLS BIFF5 (Excel 5/95), BIFF4, BIFF3, BIFF2 (Excel 2.x–4.x): read and basic data output. Writer support is narrower than parser support. BIFF2–4 are single-sheet; BIFF2–5 have 16384-row/256-column limits. Non-Latin text and formula writes may be rejected by verification. Use BIFF8/XLSX when the legacy engine cannot represent the requested content; never silently switch the user's requested format.
- Pre-standard Excel 2007 Beta 2 XLSB dialect: rejected on invalid decoded sheet metadata; LibreOffice may also lose sheets, which is rejected. This is a retained negative fixture, not supported coverage.
- XLSB (Excel 2007+ BIFF12): read and data-only creation/rewriting. The CE writer does not preserve formulas. Formula-bearing XLSB output is rejected, not claimed supported. LibreOffice imports but does not export XLSB. Formula-preserving XLSB writing is unsupported by the bundled Ubuntu engines; offer XLSX/ODS with preserved formulas or an explicitly requested data-only XLSB, never a Windows dependency or silent formula removal.
- ODS/FODS, Excel 2003 XML (XLML): read/write data and supported formulas; full application-specific objects/layout are not guaranteed.
- CSV/TSV/UTF-16 TXT/HTML: single-sheet interchange. No macros/formatting/multiple-sheet preservation. The verifier rejects type/leading-zero/encoding changes. Formula-bearing export may need an explicitly requested values-only projection prepared separately; the tool never silently removes formulas.
- Password-encrypted, corrupt, unsupported, or expansion-limit inputs: return a concrete error; do not create a misleading output. Protection is not permission to bypass it.

Large data: input cap 100 MiB, OOXML expanded cap 256 MiB and 10000 ZIP members, read output capped by requested rows. These are operational bounds, not every file size supported. Never claim “all formats/all versions” from generated round trips alone. The retained test report distinguishes independently authored fixtures, generated format probes, formula semantics, package preservation and real application checks.

## Engine limits versus CLI limits

The CLI covers a guarded common subset, not everything possible on Ubuntu. See [Ubuntu operations](ubuntu-operations.md) for direct openpyxl/UNO workflows: existing-book formatting, structural edits, tables, validation, analysis and PDF export. A task-specific full rewrite does not inherit the package editor's byte-preservation guarantee.

- Formula evaluation is LibreOffice Calc semantics, not a Microsoft Excel compatibility guarantee. Excel-only/add-in functions, VBA UDFs, external data, dynamic arrays and newer functions may differ or fail. Preserve formula text and report unsupported results; do not replace them with guessed values.
- VBA may be retained as opaque package data in the preservation route, but running/debugging VBA, COM, ActiveX and Excel add-ins is not supported. LibreOffice Basic is not an equivalent execution engine. Macro-bearing rewrites are not covered by the untouched-package guarantee.
- Power Query refresh, Power Pivot/DAX/Data Model execution, proprietary connectors, Solver/add-ins, slicers and pivot cache refresh are not covered by the bundled tool. Existing opaque objects may survive package edits; this does not prove they can be created/refreshed. Ordinary summaries/pivots can instead be computed as data in Python when that meets the request.
- openpyxl can create/edit ordinary OOXML structures, but may drop unsupported objects/extensions on load/save, and does not automatically maintain all dependent formulas, names, tables or chart references after structural edits. Inventory the affected features and verify dependencies explicitly. New XLSM creation does not generate a VBA project.
- Password decryption/encryption is not bundled in the CLI. Optional Ubuntu libraries such as msoffcrypto-tool require a separate installation/compatibility check and a user-supplied password handled outside command-line arguments/logs; they are not a guarantee for every encryption scheme. Do not bypass protection or present encrypted inputs as corrupt merely because an engine cannot open them.
- PDF/printing is a rendering operation, not an editable-workbook round trip. Fonts, locale, print areas, pagination and chart rendering can differ from Excel. Inspect the actual rendered pages before claiming layout fidelity.
- Corruption recovery, giant workbooks, beta dialects and unsupported legacy encodings have no universal guarantee. Prefer bounded/streaming reads or explicit compatible output; preserve the original and report the concrete limit when no installed Ubuntu route satisfies the request.
